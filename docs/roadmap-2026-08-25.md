# Roadmap: single-voice + память + UX (25.08.2026)

Сводный план реализации всех решений этой недели: single-voice архитектура,
`memory-design.md` (rev 2.1), план фиксов Опуса, остатки UX-аудита (~80 находок).

**Модель исполнения:** каждый пакет — Opus-субагент (reasoning effort xhigh) в
изолированном worktree; после пакета — code-review (уровень high) вторым
агентом + прогон тестов; мерж — по зелёному ревью. Пакеты внутри фазы, не
трогающие общие файлы, идут параллельно.

**Три принципа порядка:**
1. **Не полировать умирающее.** Треть UX-находок (рендер результатов воркера,
   якорные редактирования, фокус-тексты, тексты /stop) живёт в путях, которые
   single-voice удаляет. Сначала переделка, потом полировка того, что осталось.
2. **Схема и фундамент раньше потребителей.** owner.timezone, расширение
   daemon_events, процесс-хардening — предпосылки почти всего.
3. **Один несущий пакет за раз.** Фазы 1 и 2 меняют operator-daemon.ts в одних
   и тех же местах (конверт, очередь) — их пакеты последовательны; всё
   остальное параллелится.

## Правила для субагентов-исполнителей

- Один пакет = один worktree = одна ветка `track/<номер>-<slug>`.
- Перед кодом — прочитать `dialogue-flow.md` (поведение), `memory-design.md`
  (дизайн), релевантные находки аудита; план в начале работы, тесты на новые
  контракты (бюджеты рендеров, идемпотентность, классификатор пауз).
- Ничего не показывать пользователю as-is из тредов — проверять на каждом
  изменении доставки (правило single-voice).
- После пакета: самопроверка по DoD фазы + code-review high вторым агентом +
  полный прогон тестов; находки ревью чинятся до мержа.
- Пакеты фаз 1 и 2 не параллелить между собой (общие файлы: operator-daemon
  конверт/очередь, policy, storage).

### Отложенные issue пакета 1.5 (после ревью)

Закрыто по ревью (было в этом списке как долг): настоящий детач в рантаймах
(`abandon(turnToken)` снимает `active` и добивает ребёнка SIGKILL, `finally`
чистит слот только если он всё ещё наш); refine `WATCHDOG_GRACE_SECONDS >
OPERATOR_INTERRUPT_GRACE_MS`; гард одного активного хода в тестовом
`FakeRuntime`; ход, брошенный в очереди, не стартует провайдера; гейт по любой
полосе (×3 бюджет для не-user); герметичность детача (поздний result зомби не
трогает сессию/usage); `reportLostDigest` вместо голого `failRelay`; часы
молчания треда — в `thread_last_event_at:` (переживают рестарт); `commandId`
читается из конверта события (`EventBaseFields`), тест гонит реальную форму
стрим-элемента через парсер провода.

Закрыто по реверификации: гейт watchdog'а читает реальных ждущих из
`telegram_ingress` (депта полос тождественно ненулевая из-за пампа — тихий ход
умирал бы через 6 минут без единого ждущего); зомби-ход владельца без нового
сообщения теперь **ретраится** (джоба replay + честная строка «Ответ завис —
попробую ещё раз») и user-полоса будится по `run_after`; дедлайн
compact/handoff — половина `turnTimeoutMs`; `now` проброшен в троттл строки;
`thread_last_event_at` и `thread_stall_reported_at` на одном источнике времени;
мутация `this.active === child`, `abandoned_before_start`, `withRuntimeDeadline`
и фолбэк `correlationId` покрыты тестами; молчаливый catch в хелперах логируется.

Осталось осознанным долгом:

- **Зомби-процесс живёт до SIGKILL-подтверждения.** `abandon` шлёт SIGKILL и
  сразу отпускает слот; подтверждения смерти (`close`) никто не ждёт, и для
  провайдера с несколькими детьми (обёртка-шелл) внуки могут пережить родителя —
  лечится группой процессов (`detached: true` + `kill(-pid)`), это отдельная
  задача по хардненингу процессов.
- **`maintain`/`compact`/`switchProvider` теперь с дедлайном

  токена у них нет, и повторно они не запускаются — на дедлайне ресурс
  чинится (`runtime.abandon()`), а вызов падает в лог.
- **Каскад зависаний троттлится по чату (1 строка/мин).** Владелец не узнает

- **Non-user бюджет — множитель ×3, не отдельный конфиг.** Если дайджест-полоса
  окажется живее в проде, нужен свой ключ.
- **e2e на живом T3**: эхо `commandId` проверено на форме контракта и через
  парсер провода, но не против настоящего сервера.
- **Ретрай зомби-хода наследует общий потолок ingress-джобы** (8 попыток,

  владельцу общий «не удалось обработать сообщение» — отдельного текста под

### Отложенные issue пакета 4.1 (после двух ревью)

Закрыто по ревью: backpressure `DraftWriter` (коллапс цепочки), гард
`isMessageNotModified` в edit-ветке `updateDraft`, троттл chat action и
отдельная метрика, порог уведомления по РАБОТЕ (а не по форме пачки), учёт
`!media`/`maxInputBytes`/OCR, дедуп на остатке, пульс ожидания в очереди
полос, инжектируемые интервалы, безличный регистр + строка в конверт.

Осталось:

- **Нулевой запас между пульсом и троттлом (D).** `LIVENESS_PULSE_INTERVAL_MS`
  (4000) равен `CHAT_ACTION_MIN_INTERVAL_MS` (4000): любой дребезг таймера
  съедает пульс, а следующий придёт только через интервал — разрыв 8 с при
  времени жизни индикатора ~5 с. Окно троттла разумнее сделать ~3 с (заведомо
  ниже каденции производителей), но это меняет и защиту от бурста — считать
  вместе, не по одной константе.
- **`drain()` без внешнего `.catch` (E).** Всё, что вне внутреннего `try`
  (например бросок из `classifyTelegramDeliveryError`), отвергнет `chain` — и
  тогда `closePreview`/`finalize`, на которых ждёт финальный ответ, получат
  reject, а последующие звенья не выполнятся вовсе. Сегодня недостижимо
  (классификатор тотален: только instanceof и чтение полей), поэтому
  оборонительная правка, а не бой.

- **Строка в конверте — контекст, не гарантия.** Оператор узнаёт, что демон уже
  написал «Расшифровка: …», из `mediaContext`, то есть изнутри фенса
  недоверенного текста (0.5). По ревью (F) формулировка переписана фактом без
  повелительного наклонения — демон не отдаёт приказы из недоверенной зоны, —
  но именно поэтому повтор фразы Оператором ничем не запрещён.
  Настоящее место — секция конверта; трогать сборку конверта в 4.1 было нельзя
  (параллельный 2.2). Кандидат в 5.x вместе с ревизией секций.
- **Пропуск по бюджету батча (512 МиБ) не виден уведомлению.** Оно считается по
  заявленным метаданным до скачивания, а бюджетный дроп происходит внутри
  `ingestOne` — пачка тяжелее бюджета может получить обещание расшифровки,
  которой не будет. Достижимо только с локальным Bot API.
- **`awaitingIngress` ключуется чатом, не сообщением.** Две ждущие джобы в одном
  чате делят одну запись, и первая же стартовавшая снимает индикатор у обеих.
  Дёшево и безвредно (следующий ход зажжёт свой), но не точно.
- **Потолок ожидания 60 с — обрыв, а не сообщение.** Если очередь занята
  дольше, чат честно замолкает вместо «жду ещё». Осознанно: durable-строка
  «всё ещё в очереди» — это уже голос, а не индикация.
- **`DraftWriter.replace` без вызывающих** (унаследовано). Оставлен: публичный
  метод пакета, семантика с max-wait корректная; удалять — отдельной уборкой.
- **`.catch` на `sendChatAction` в демоне формально мёртв** — наша реализация
  больше не отвергает. Оставлены сознательно: `TelegramTransport` — интерфейс,
  и другая реализация (или фейк в тесте) вправе бросать.
- **Пороги «длинного медиа» по заявленным метаданным.** `duration` у
  документа-аудио отсутствует всегда — такой файл проходит как короткий (пульс
  при этом идёт). Настоящая длительность требует ffprobe, то есть того самого
  скачивания, которое строка должна опережать.
- **Пульс обогащения не различает вид работы.** Один `typing` на скачивание,
  ffmpeg, STT и OCR; `upload_voice`/`upload_document` были бы точнее, но
  Telegram рендерит их как «отправляет голосовое/документ», чего демон не делает.
